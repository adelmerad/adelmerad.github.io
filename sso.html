01The goalL'objectif

When every internal application manages its own accounts, people end up with one password per app, and disabling someone means going through every app one by one. The goal was a single identity server: users sign in once, applications delegate authentication to it, and administrators manage accounts and roles in one place. Quand chaque application interne gère ses propres comptes, chacun finit avec un mot de passe par appli, et désactiver quelqu'un oblige à passer par toutes les applis une par une. L'objectif : un seul serveur d'identité. Les utilisateurs se connectent une fois, les applications lui délèguent l'authentification, et les administrateurs gèrent comptes et rôles au même endroit.

03Key decisionsChoix techniques

PKCE for every clientPKCE pour tous les clients

Only the Authorization Code flow is enabled, and PKCE is mandatory, so a stolen authorization code is useless without the verifier. Seul le flux Authorization Code est activé, et PKCE est obligatoire : un code d'autorisation volé ne sert à rien sans le verifier.

No tokens in the browserAucun token dans le navigateur

The BFF stores the tokens server-side. The browser only holds an HttpOnly cookie with an opaque session id. The id_token is checked against the SSO's JWKS keys: signature, issuer, audience and expiry. Le BFF garde les tokens côté serveur. Le navigateur n'a qu'un cookie HttpOnly avec un identifiant de session opaque. L'id_token est vérifié avec les clés JWKS du SSO : signature, émetteur, audience et expiration.

Rotation and proactive refreshRotation et renouvellement anticipé

Refresh tokens are rotated on each use. The BFF renews the access token when it expires in under 60 seconds. An invalid refresh token closes the session; a network or SSO outage does not sign the user out. Les refresh tokens changent à chaque utilisation. Le BFF renouvelle l'access token quand il expire dans moins de 60 secondes. Un refresh token invalide ferme la session ; une panne réseau ou du SSO ne déconnecte pas l'utilisateur.

Roles per applicationDes rôles par application

Besides the global Admin role, each application declares its own roles: "Employee" in HR and "Employee" in Stock never interfere. An account with no role in an application is refused at sign-in. En plus du rôle global Admin, chaque application déclare ses propres rôles : « Employé » dans les RH et « Employé » dans le stock ne se mélangent jamais. Un compte sans rôle dans une application est refusé à la connexion.

Admin safeguardsGarde-fous d'administration

The last administrator cannot be removed, an admin cannot lock themselves out, and accounts can be suspended until a date. A disabled or suspended account is checked again before any token is issued. Impossible de supprimer le dernier administrateur ou de se bloquer soi-même, et les comptes peuvent être suspendus jusqu'à une date. Un compte désactivé ou suspendu est revérifié avant l'émission de chaque token.

Secrets out of the codeLes secrets hors du code

Connection strings, client secrets and the first admin password live in .NET user-secrets on each machine, never in the repository. Chaînes de connexion, secrets clients et mot de passe du premier admin vivent dans les user-secrets .NET de chaque machine, jamais dans le dépôt.

05What I learned, and what's nextCe que j'ai appris, et la suite

  • How OAuth2 and OpenID Connect really work, beyond calling a library: authorization codes, PKCE, token lifetimes, signature validation.Comment OAuth2 et OpenID Connect fonctionnent vraiment, au-delà d'une librairie : codes d'autorisation, PKCE, durée de vie des tokens, validation des signatures.
  • Why the BFF pattern is the safer choice for web apps: the browser has nothing worth stealing.Pourquoi le pattern BFF est le choix le plus sûr pour une appli web : le navigateur n'a rien qui vaille la peine d'être volé.
  • Designing for failure: deciding when to close a session and when to keep the user signed in.Penser aux pannes : décider quand fermer une session et quand garder l'utilisateur connecté.

Next steps: single logout across all applications at once, and applying role changes without waiting for the next sign-in. Pistes d'amélioration : une déconnexion unique sur toutes les applications à la fois, et la prise en compte d'un changement de rôle sans attendre la connexion suivante.
